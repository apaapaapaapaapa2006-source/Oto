# Motion Editor（モーションデザイン編集アプリ）

ブラウザで動く、スマホ（iPhone）優先のモーションデザイン編集アプリです。成果物は **`index.html` 1 ファイル**（CSS・JS はすべてインライン、ビルド工程なし、サーバーなし）。

- 初回起動時は空のプロジェクトを開きます。サンプル素材やデモは入っていません。
- 動画の書き出しは「書き出し」ボタンを押したときだけ行います。
- 編集・再生・Undo/Redo・保存は通信なしで動きます（実行時に外部 API・AI は呼びません）。

```
motion/
├── index.html      … アプリ本体（これだけで動作）
├── README.md
└── tests/          … 開発用テスト（Playwright）。index.html には含まれません
    ├── editor.spec.js    iPhone 端末エミュレーション（WebKit / Chromium）
    ├── desktop.spec.js   PC（マウス・キーボード）
    ├── export.spec.js    MP4 書き出し・フレーム比較・フォールバック
    ├── selftest.spec.js  ?test=1 の内蔵セルフテスト
    ├── helpers.js / server.mjs / playwright.config.js / package.json
    └── fixtures/   … テスト用の画像（160×120 PNG）と自作の箱フォント（TTF）
```

## GitHub Pages への置き方

**このリポジトリの場合**：`.github/workflows/pages.yml` がリポジトリ全体を GitHub Pages に公開するので、`main` に入れるだけで
`https://<ユーザー名>.github.io/<リポジトリ名>/motion/` で開けます（例：`https://apaapaapaapaapa2006-source.github.io/Oto/motion/`）。

**単体で置く場合**：

1. 新しいリポジトリを作り、`index.html` をルートに置いて push します（`tests/` と `README.md` は任意）。
2. GitHub の **Settings → Pages** で「Deploy from a branch」を選び、ブランチ `main`・フォルダ `/ (root)` を指定します。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。

HTTPS で配信する必要があります（WebCodecs・crypto.subtle・Web Share などは安全なコンテキストでのみ動くため）。

## 基本操作

### スマホ（縦画面）

画面は上から **プレビュー → 再生ボタン → タイムライン**、プロパティ等は下の **ボトムシート**（タブ：追加 / プロパティ / レイヤー / シーン / 素材）。タブをもう一度タップすると閉じ、シート上端の取っ手をタップ / ドラッグで大きさを切り替えます。

| 場所 | 操作 |
|---|---|
| プレビュー | タップで選択（何もない所をタップで選択解除）、1 本指ドラッグで移動、2 本指ピンチで拡大縮小、2 本指ひねりで回転 |
| タイムライン上端の目盛り | タップ / なぞると再生ヘッドが移動（スクラブ） |
| タイムラインの空き領域 | 1 本指でスクロール、2 本指ピンチでズーム（左上の −／＋ でも可） |
| レイヤーのバー | タップで選択。選択中のバーはドラッグで開始時間を移動、両端のつまみで開始・長さを変更 |
| ◆（キーフレーム） | タップで選択（時刻・値・イージングを編集）、左右にドラッグで時刻を変更 |
| シーン行 | シーンをタップでその先頭へ、シーン右端の縦棒をドラッグで長さを変更（後ろのシーンは詰めて並ぶ） |
| 「?」 | タップすると説明が出ます |

### PC / 横画面（3 カラム）

左：追加 / レイヤー / シーン / 素材、中央：プレビュー + タイムライン、右：プロパティ。

- 選択したレイヤーの四隅のハンドルで大きさ変更（**Shift で縦横比を固定**）、上の丸で回転（Shift で 15° 刻み）。テキストは四隅で拡大率を変更。
- Shift + クリックで複数選択。ファイルを画面にドラッグ&ドロップで素材を読み込み。
- キー：`Space` 再生 / 停止、`←` / `→` 1 コマ移動（Shift で 10 コマ）、`Home` / `End`、`Ctrl+Z` 元に戻す、`Ctrl+Shift+Z`（または `Ctrl+Y`）やり直す、`Delete` 削除、`Ctrl+D` 複製、`Esc` 選択解除。
- `Ctrl` + ホイール（トラックパッドのピンチ）でタイムラインをズーム。ボタンにマウスを乗せると説明（ツールチップ）が出ます。

### キーフレームとアニメーション

1. 再生ヘッドを動かし、プロパティ横の **◆** を押すと、その時刻にキーフレームを追加 / 削除します。
2. ◆ が黄色い枠のプロパティは「アニメーション中」です。値を変えると今の時刻に自動でキーフレームが打たれます。
3. タイムラインの ◆ をタップすると、プロパティ欄で **イージング**（リニア / イーズイン / イーズアウト / イーズインアウト / カスタムのベジェ / スプリング）を選べます。カーブは動くプレビュー付きで、ベジェはグラフ上の点をドラッグ、スプリングは硬さ・減衰・重さのスライダーで調整します。
4. **アニメーション（プリセット）**：スライド / フェード / 拡大縮小を、方向・距離・遅延・長さ・イージングを指定して「イン（登場）」「アウト（退場）」に適用します。生成されるのは通常の編集できるキーフレームで、同じ枠への再適用は置き換え、元に戻すで取り消せます。
5. **ステージャー**：レイヤーパネルの「複数選択」をオン（PC は Shift + クリック）にして複数選ぶと、プロパティ欄に表示されます。順序（リストの上から / 下から / シード付きランダム）と間隔を指定して開始時間をずらします。
6. **カーソルレイヤー**：プレビュー上の番号付きの点（経路点 = 目標位置）をドラッグ、「再生ヘッド位置に経路点 / クリック」で追加。クリック時刻には波紋が出ます。「なめらかさ」で経路のスムージングと各点での減速を調整します。

## 保存と読み込み

- **自動保存**：編集内容はこのブラウザ内（IndexedDB）に自動で保存され、次に開いたときに復元されます。ヘッダーに「保存済み / 未保存の変更あり / 保存中…」を表示します。
- **素材**：画像（PNG / JPG / WebP / SVG）とフォント（TTF / OTF / WOFF2）は、元のファイルを改変せず Blob として IndexedDB に保存し、SHA-256 を記録します。フォントは FontFace API で登録され、テキストの「フォント」欄で選べます。
- **素材が見つからない場合**：プレビューに赤枠のプレースホルダーを表示し、プロパティ欄と「素材」タブに **「再リンク」** ボタンが出ます。
- **ファイルに保存**：メニュー（左上の ≡）→「ファイルに保存…」で、素材を base64 で埋め込んだ 1 ファイル（`<プロジェクト名>.motion.json`）を作ります。
  - iPhone：「共有（ファイルに保存）」→「“ファイル”に保存」。共有できない場合は「ダウンロード」。
  - PC：「ダウンロード」。
- **ファイルを開く**：メニュー →「ファイルを開く…」（PC はドラッグ&ドロップでも可）。読み込み時にスキーマ検証を行い、形式エラーは項目ごとに表示します。素材のハッシュが一致しない場合も警告します。

## 書き出し方法

1. ヘッダーの **「書き出し」** を押すと、解像度・fps・長さと、この端末で使える書き出し方式を確認するダイアログが開きます。
2. **「MP4を書き出す」** で開始します。進捗バーとキャンセルボタンが出ます。書き出し中は Wake Lock API で画面のスリープを防ぎ、「アプリを切り替えないでください」と表示します。
3. 完了したら「ダウンロード」、iPhone では「共有 / 保存」→「ビデオを保存」または「“ファイル”に保存」。

仕組み：全フレームを `t = i / fps` で `renderFrame` に描き（OffscreenCanvas、無ければ通常の Canvas）、WebCodecs の `VideoEncoder`（H.264）でエンコードして MP4 にまとめます。実時間ではなくフレーム単位で処理するのでコマ落ちしません。1 フレーム目の前に `document.fonts.ready` と全画像のデコード完了を待ちます。

- **iPhone / iPad** では 1080p（1920×1080 相当）が上限です。それを超える設定では理由を表示し、1080p に縮小して書き出します。
- **H.264 の VideoEncoder が使えない環境**では、MediaRecorder による実時間録画に切り替え、「コマ落ちの可能性あり」と表示します（形式は MP4 または WebM）。

## セルフテストの開き方

`index.html?test=1` を開く（またはメニュー →「セルフテストを開く」）と、画面上でテストが走り、結果を一覧表示します。iPhone で直接確認できます。編集中のプロジェクトには触れません（テスト用の IndexedDB は別名で作って最後に削除します）。

内容：補間（線形・範囲外・複数区間・色・カーソル経路）、全イージング（端点・単調性・既知の値・ベジェ解法の精度）、スプリング（解析解を数値積分と照合）、決定性（同じ時刻を 2 回描画してピクセル完全一致。描画順を変えても一致。`Date.now` / `Math.random` / `performance.now` を使っていないことも確認）、スキーマ検証（正常データの受理と異常 17 ケースの拒否）、保存→読み込みの往復一致（.motion.json と IndexedDB、素材のバイト列と SHA-256 まで）、MP4 mux の構造、書き出し機能の対応状況（参考表示）。

## 構成について（要件からの差分と理由）

- **MP4 の mux は外部ライブラリを使わず自前で実装しました**（`index.html` 内の `MP4` モジュール、約 100 行）。要件では Mediabunny 等を 1 つ読み込むことが許されていますが、自前にすると (1) 書き出しもオフラインで動く、(2) CDN の障害やバージョン変更の影響を受けない、(3) 外部ライブラリ「なし」の原則どおりになる、ためです。H.264（AVCC 形式）の映像 1 トラックだけを `ftyp → moov → mdat`（先頭に moov を置く faststart 形式）で書きます。説明情報（avcC）がエンコーダから得られない環境のために、SPS/PPS から avcC を組み立てる処理も入れています。生成した MP4 は ffprobe / ffmpeg で検証しています（下記）。
- 外部ライブラリの読み込みはありません（CDN への通信は発生しません）。

## 既知の制限

- **WebKit エンジンでの Playwright テストは、この開発環境では実行できていません。** ネットワーク制限で Playwright の WebKit をダウンロードできなかったため、同じテスト（`editor.spec.js`・`selftest.spec.js`）を Chromium の iPhone 15 エミュレーションで実行しました。`npm run test:webkit` で実行できるようにしてありますが、結果は未確認です。**実機の iPhone でも未確認**です。特に次の Safari 固有の動作は未検証です：WebCodecs の H.264 エンコード、OffscreenCanvas からの VideoFrame 作成、Wake Lock、Web Share での .json / .mp4 の共有、OffscreenCanvas での読み込みフォントの描画。iPhone ではまず `?test=1` のセルフテストで確認してください。
- 書き出した動画は YUV 4:2:0 への変換と圧縮のため、`renderFrame` と完全には一致しません（上記のとおり PSNR 約 40 dB）。プレビューと書き出しの「描画」は同じ関数です。
- 書き出し中のデータはメモリ上に保持します。長尺・高解像度では端末のメモリが足りなくなることがあります（特に iPhone）。MP4 は 4 GB まで。書き出し中にアプリを切り替えると失敗することがあります。
- MediaRecorder へのフォールバックは実時間録画のため、コマ落ちする可能性があり、形式（MP4 / WebM）はブラウザ次第です。
- システムフォント（ゴシック・明朝など）は OS ごとに実体が違うため、端末によって文字の見た目が変わります。同じ見た目にしたい場合はフォントファイルを読み込んで使ってください。文字間隔が 0 以外のときは 1 文字ずつ描くため、カーニングは効きません。
- スプリングのイージングは「次のキーフレームまでの時間」に収まるよう伸縮します（物理的な秒数ではありません）。
- キーフレームの時刻はレイヤーの開始からの相対時間です。レイヤーを移動するとアニメーションも一緒に動きます。レイヤーの長さを変えても「アウト」プリセットのキーフレームは自動では動かないので、必要なら再適用してください。ステージャーは開始時間だけをずらします（長さは変えません）。
- タイムラインに表示されるのは、再生ヘッドがあるシーンのレイヤーだけです。
- Undo 履歴は最大 200 件で、再読み込みすると消えます。
- 自動保存はこのブラウザの IndexedDB です。Safari はしばらく使わないサイトのデータを削除することがあるため、大事なプロジェクトは「ファイルに保存」してください。
- 一度開いた後の編集・再生・保存・書き出しは通信なしで動きますが、Service Worker が無いため、オフラインでページを最初から開き直せるかはブラウザのキャッシュ次第です。
- ブラウザ内の素材の保存は、プロジェクトから参照されなくなったものを次回起動時に削除します。
